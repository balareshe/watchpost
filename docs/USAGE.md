# Watchpost 使用手册

面向「已经部署好、准备日常使用」的人。如果你还没部署，先看 [README](../README.md) 快速开始。

这份手册讲四件事：**第一次怎么进后台**、**后台每个页面怎么用**、**前台看到的是什么**、**日常怎么维护**。

---

## 1. 第一次进入后台

### 1.1 打开安装向导

浏览器访问 `https://<你的域名>/admin/`。

如果这是全新实例（没有任何用户、也没配 `ADMIN_EMAILS`），页面会自动显示**首次安装**，而不是登录框。

### 1.2 抄初始化令牌

令牌是一次性的，打印在服务启动日志里：

```bash
docker compose logs status-api | grep 初始化令牌
```

输出形如：

```
初始化令牌（一次性，容器重启会变）: fkMoG6g5gtyXpH7KKNSG1XYAvG9dBWh0
```

把它填进安装页的「初始化令牌」。

> **为什么需要这一步**：如果不做验证，任何公网访问者发现你的实例就能抢先注册成管理员。
> 令牌只存在内存里，容器重启会重新生成，也不会写进任何文件。

### 1.3 填管理员邮箱与 SMTP

| 字段 | 说明 |
|---|---|
| 管理员邮箱 | 登录后台用这个邮箱收验证码，**不需要密码** |
| SMTP 服务器 / 端口 / 账号 / 密码 | 可选。填了才能收到登录验证码和告警邮件 |

**SMTP 可以先跳过**，安装完在后台「通知」页再配。但没配之前你收不到验证码，只能用日志里的验证码登录（见 1.5）。

常见 SMTP 参考（端口与加密方式要配套）：

| 服务 | 服务器 | 端口 | 加密方式 |
|---|---|---|---|
| 阿里云邮件推送 | `smtpdm.aliyun.com` | 465 | SSL |
| 腾讯企业邮 | `smtp.exmail.qq.com` | 465 | SSL |
| Gmail | `smtp.gmail.com` | 465 | SSL（用应用专用密码） |
| 自建 Postfix | 你的域名 | 587 | STARTTLS |

### 1.4 完成安装

点「完成安装」即创建第一个管理员并自动标记安装完成。**此后安装页永久关闭**，再访问 `/admin/` 就是正常登录框。

想再加管理员，去后台「用户」页添加。

### 1.5 收不到验证码怎么办

按顺序排查：

1. **后台「通知」页是否启用了 SMTP**。登录用的是 `.env` 里的 `SMTP_*` 或后台保存的配置，两处任一可用即可。
2. **翻日志拿验证码**。无论邮件是否成功，验证码都会明文打印：
   ```bash
   docker compose logs status-api | grep 验证码
   ```
   形如 `[login] you@example.com 验证码 053882（10 分钟内有效）`。
3. 有 60 秒冷却：刚请求过就再点，会提示「请求过于频繁」。

> 安全提示：这条日志明文通道意味着**能看容器日志的人就能登录后台**。
> 如果你把日志转发到公共平台，务必关掉或加密，详见 [SECURITY](../SECURITY.md)。

### 1.6 登录规则

| 项 | 值 |
|---|---|
| 验证码 | 6 位数字，10 分钟内有效 |
| 错误次数 | 连续错 5 次作废，需重新获取 |
| 重发冷却 | 同一邮箱 60 秒 |
| 每小时上限 | 同一邮箱 5 次、同一 IP 10 次 |
| 会话有效期 | 7 天 |

## 2. 后台使用

后台左侧导航按角色显示，无权限的页面不会出现。

### 2.1 概览

一眼看全局，六块数字：

- **当前状态**：有节点不可用就标红
- **监控节点**：Gatus 内置节点 + 自定义节点总数
- **今日可用率**：当天所有探测的成功率（取自 Gatus 小时聚合）
- **未恢复事件**：还没标记「已恢复」的工单数
- **公告**：总数与置顶数
- **维护窗口**：总数与进行中的数量

下方是「节点状态」列表（名称 + 延迟 + 是否自定义）和「最近事件」5 条。

### 2.2 工单

所有事件的列表视图，支持按**状态**、**严重程度**、**关键词**（标题/组件/处理人）筛选。

点任意一行进详情页，那里能做：

| 操作 | 说明 |
|---|---|
| 改状态 | 排查中 → 已定位 → 修复中 → 监控中 → 已恢复（**允许跳级**） |
| 改严重程度 | 重大 / 严重 / 一般 / 提示 / 维护 |
| 改处理人 | 填值班同事名字 |
| 发布进度 | 写说明 + 选状态，会追加到时间线；提供 5 个模板可一键填充 |
| 删除工单 | 不可恢复，需确认 |

> 自动开单产生的事件，恢复正常后 watcher 会自动追加「已恢复」并关单，无需手动处理。

### 2.3 事件

和「工单」是同一份数据的另一种视图，偏重**新建**：

- 新建事件：标题（中/英）、受影响组件（从探针与节点里选，可多选）、严重程度、状态、概要、首条进度说明
- 已有事件：下拉直接改状态、删除、展开「发布进度」

> 手动新建的事件**不会**被 watcher 自动关闭，需要你自己改状态。

### 2.4 公告

- **发布公告**：标题、级别（普通 / 重要-橙色）、正文（支持换行）、是否置顶
- **已发布**：列表 + 删除

公告会出现在前台最顶部，置顶的排前面；也会进 RSS。点公告卡片可以进独立详情页 `/announcement.html?id=...`。

### 2.5 维护窗口

**这块最有用**：窗口期内 watcher 既不重试也不自动开单，避免计划内运维被当成故障告警。

创建方式：

1. 填标题
2. 选开始时间（日期 + 时分，分钟按 5 分钟粒度）
3. 选结束时间（不能早于开始，会红字提示）
4. 或者用**快捷按钮**：现在起 1 小时 / 现在起 2 小时 / 今天 00:00–06:00 / 本周日 02:00–04:00
5. 选影响组件（从探针列表里点选）
6. 可选说明

创建后前台会显示橙色横幅「XX 维护中，预计 … 完成」。

### 2.6 节点

**排序**：上下移调整前台展示顺序。内置节点来自 Gatus 配置，自定义节点由 watcher 自己探测。

| 类型 | 来源 | 探测方 | 历史长度 |
|---|---|---|---|
| 内置 | `config/gatus/config.yaml` | Gatus | 受 Gatus 保留上限约束（默认每端点约 100 条） |
| 自定义 | 本页添加 | watcher | 24 小时（96 格），重启从零累积 |

**添加自定义节点**需要「名称 + 完整 URL + 探测间隔（≥30 秒）」。适合监控 Gatus 配置里不方便加的目标。

**慢响应阈值**：每个节点可以单独设（毫秒），留空跟随全局设置。填 `0` 表示该节点不判定慢响应。

> 自定义节点的 URL **不会**在匿名接口里返回，只有登录用户或服务令牌能看到。

### 2.7 用户（仅管理员）

| 角色 | 权限 |
|---|---|
| 管理员 `admin` | 全部权限，含账号管理 |
| 维护人员 `maintainer` | 可操作事件/公告/维护/节点，**不能**管账号 |
| 只读 `viewer` | 只能看概览 |

- 添加用户：邮箱 + 角色 + 备注名（可空）
- 停用 / 启用：停用后无法登录，但历史记录保留
- 删除：**该邮箱的所有会话立即失效**
- 不能删除自己

> `.env` 里 `ADMIN_EMAILS` 配置的邮箱**始终**能登录，即使从用户表里删掉——这是防止把自己锁在门外的保险。

### 2.8 系统设置（仅管理员）

| 项 | 作用 |
|---|---|
| 站点名称 | 左上角显示，同时用于 RSS 标题 |
| 浏览器标题 | 标签页文字 |
| 副标题 | 名称下方说明 |
| 慢响应阈值 | 全局毫秒数，超阈值连续 N 次显示黄色；填 0 关闭 |
| 慢响应判定次数 | 连续几次超阈值才算（默认 3） |
| 站点图标 | emoji 或图片 URL |
| 自动工单文案模板 | 自动开单时生成的标题/概要/更新文案，`{name}` 等占位符会被替换 |

> 这里的「慢响应」设置**后端判定与前台标黄读的是同一份数据**，不会各说各话。

### 2.9 通知（仅管理员）

两件事：**配 SMTP** 和**写邮件模板**。

- 开关：启用事件邮件通知
- SMTP 服务器 / 端口 / 账号 / 密码 / 发件人 / 加密方式
- 主题与正文模板，可用变量：`{site}` `{title}` `{components}` `{severity}` `{summary}` `{status}` `{time}` `{url}`
- 测试发送：填个邮箱点发送，验证配置是否可用（用的是**已保存**的配置，改完记得先保存）

收件人 = 「用户」页里所有已启用账号，自动生效。

> 密码回显是打码的 `********`。保存时如果还是打码值，后端会忽略，不会把星号写进配置。

### 2.10 设置

只显示当前账号信息和登录方式说明，以及退出登录按钮。

## 3. 前台看到什么

访客访问 `https://<你的域名>/`：

| 区块 | 内容 |
|---|---|
| 公告 | 有公告才显示；置顶优先，橙色=重要 |
| 维护横幅 | 维护窗口进行中时显示橙色提示 |
| 故障横幅 | 有红色级未恢复事件时显示 |
| 状态列表 | 每个组件一行：状态点、名称、延迟、30 天可用率、详情按钮、24 小时条形图 |
| 事件日历 | 最近 4 周，按「当天出现过什么级别」上色 |
| 最近事件 | 默认 5 条，可展开 |
| RSS | `/feed.xml`，事件 + 公告各最多 30/20 条 |

**几种颜色代表什么**：

- 条形图：绿=全部成功、浅绿=≥90%、黄=≥50%、红=<50%、灰=无数据
- 状态点：绿=正常、黄=慢响应（连续 N 次超阈值）、红=不可用
- 日历：红=当天有重大事件、黄=只有一般事件、绿=正常、灰=无数据

**日历不按可用率百分比上色**，按「当天有没有出过事」。原因见 [ARCHITECTURE](ARCHITECTURE.md) 第 10 节——按百分比会出现「99.51% 全绿但其实挂过」的矛盾观感。

点「详情」展开最近探测记录表格，可以勾「只看失败」；点日历某天看当天明细。

## 4. 日常维护

### 4.1 自动开单规则

```
探测失败（Gatus 记一次）
   └─ 连续失败累计到 FAIL_THRESHOLD（默认 1）
        └─ watcher 立即对该 URL 重试 3 次（间隔 2 秒）
             ├─ 任一次成功 → 视为抖动，不记录、不通知
             └─ 3 次全失败 → 升级为 critical（红），开单并发邮件
```

想要「先观察两轮再说」，把 `FAIL_THRESHOLD` 调大（每多 1 ≈ 多等一个轮询间隔）。

**自动恢复**：连续成功 3 次 → 自动追加「已恢复」并关单。

**慢响应**：连续 3 次超阈值（默认 800ms）→ 记一条 `minor` 事件，**不发邮件、不弹横幅**，只进事件列表。

### 4.2 常用命令

```bash
docker compose ps                        # 服务状态
docker compose logs -f status-watcher    # 看自动开单/通知
docker compose logs -f status-collector  # 看数据导出
docker compose restart status-api        # 改完后端代码后重启
curl -s https://<域名>/api/health        # 版本与存活
sh deploy/verify.sh <域名>               # 上线验收（24 项）
```

排障顺序：`/api/health` → 容器状态 → 对应服务日志 → `web/data/status.json` 是否有新数据 → Caddy 反代。

### 4.3 加监控目标

两种方式：

1. **改 Gatus 配置**（推荐，有完整历史）：编辑 `config/gatus/config.yaml` 加一个 endpoint，`docker compose restart gatus`
2. **后台「节点」页加自定义节点**：不用重启，但历史只有 24 小时

### 4.4 数据备份

```bash
# 业务数据（事件/公告/维护/节点/用户/设置）
docker run --rm -v watchpost_api-data:/d -v $PWD:/o alpine \
  tar -C /d -czf /o/api-data-$(date +%F).tgz .

# 探针历史（注意 -wal 才是主体，必须整个目录拷）
docker run --rm -v watchpost_gatus-data:/d -v $PWD:/o alpine \
  tar -C /d -czf /o/gatus-data-$(date +%F).tgz .
```

> 只拷 `data.db` 只有几 KB，真正数据在 `data.db-wal` 里。

### 4.5 升级

```bash
cd /opt/watchpost

# 方式一：镜像模式（推荐）
git pull
docker compose pull && docker compose up -d

# 方式二：脚本（会先备份再升级）
sh deploy/update.sh           # 拉最新
sh deploy/update.sh v0.1.2    # 切到指定版本
```

> **镜像模式下光 `git pull` 不会更新容器里的代码**——代码在镜像里，必须 `docker compose pull`。

## 5. 常见问题

**Q：后台登录提示「验证码不正确或该邮箱无权限」？**
A：这个提示**不区分**邮箱是否存在（防枚举）。确认邮箱在「用户」页里且处于启用状态，或配在 `.env` 的 `ADMIN_EMAILS` 里。

**Q：改了后台代码没生效？**
A：`web/admin/` 是构建产物。改了 `admin-app/` 必须在本地跑 `npm run build` 再提交，部署机不装 Node。

**Q：前台条形图有的组件只有一小段，有的很长？**
A：内置节点走 Gatus，受其保留上限约束（默认每端点约 100 条结果）；自定义节点由 watcher 采样，有完整 24 小时。想让内置节点也显示 24 小时，调 `config/gatus/config.yaml` 的 `storage.maximum-number-of-results`。

**Q：维护期间还会告警吗？**
A：不会。窗口内 watcher 既不重试也不开单，慢响应判定同样跳过。

**Q：一个组件挂了，但只收到一封邮件？**
A：事件创建时发一次，恢复时再发一次（主题带 `[已恢复]`）。中间的状态变更不发邮件，避免刷屏。

**Q：能禁止访客看到状态页吗？**
A：目前没有内建鉴权。可以用 Caddy 加 basic auth，或把域名放到 Cloudflare Access 后面。
